## Key Technical Findings

### F1 — Critical: a duplicate attempt can compensate another attempt's accepted claim

The relevant operations are individually locked; the defect is a **business interleaving**, not an unsynchronized memory access:

1. Two `Match(R1)` calls read an unassigned ride and the same available driver snapshot.
2. A claims D1 for R1. B calls Claim for the same pair; Driver.Claim returns `(false,nil)` because that claim already exists ([internal/driver/driver.go:91](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/driver/driver.go#L91)).
3. A assigns R1 and creates its offer. B pauses just before its own Assign. The saga ignores Claim's `changed` result: `if _, err := s.drivers.Claim(...)` ([internal/dispatch/service.go:153](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/service.go#L153)).
4. Driver accepts A's offer. R1 is DRIVER_ACCEPTED; D1 is BUSY.
5. B resumes Assign. Assign only recognizes a duplicate in DRIVER_ASSIGNED, so DRIVER_ACCEPTED causes conflict ([internal/ride/ride.go:98](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/ride/ride.go#L98)).
6. B compensates with `s.drivers.Release(ctx,D1,R1)`. Release checks only status OFFERED/BUSY and ride ID; it frees D1 despite R1 remaining accepted ([internal/dispatch/service.go:164](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/service.go#L164), [internal/driver/driver.go:118](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/driver/driver.go#L118)).
7. `Match(R2)` claims D1, then R2 accepts. **R1 and R2 are both DRIVER_ACCEPTED with assignedDriverId D1; D1's currentRideId is R2.** Offer-store uniqueness blocks only PENDING, so it does not reject the second accepted history ([internal/dispatch/offer.go:80](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/offer.go#L80)).

**Verification:** reviewer goroutine/channel scheduling wrappers reproduce this deterministically under `-race` on **both revisions**, with real repositories/domain/services. The default one-bus-per-process wiring serializes same-ride event handlers, so this trace is not claimed as a normal HTTP-only exploit. Concurrent duplicate matching is nonetheless an explicitly supported/tested command scenario ([internal/dispatch/concurrency_test.go:84](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/concurrency_test.go#L84)), and ADR-002 claims state guards remain safe even if duplicates run concurrently ([docs/adr/ADR-002-concurrency.md:119](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/docs/adr/ADR-002-concurrency.md#L119)). Serial dispatch delivery is a mitigation, not a safe compensation mechanism for that claimed scope.

**Recommendation:** preserve attempt ownership. At minimum do not compensate a claim this attempt did not acquire; use an expected phase/reservation generation when undoing a newly acquired claim, or serialize a complete matching attempt per ride. Ensure rollback cannot release a claim that has become an accepted trip. Add the combined duplicate-match/accept/second-ride trace as a regression.

AC-08 3/4 and distributed idempotency 2/3 assess duplicate side effects. Data architecture 1/2 and consistency 1/2 assess cross-record invariants; failure handling 1/2 assesses unsafe compensation. No fourth penalty or total cap.

### F2 — Major: expired deadline is not checked on acceptance

`checkOffer` treats every PENDING offer as actionable. Neither `Accept`, Ride.Accept nor `Offer.resolve` compares `clock.Now()` with `expiresAt` ([internal/dispatch/service.go:339](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/service.go#L339), [internal/dispatch/service.go:207](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/service.go#L207), [internal/dispatch/offer.go:48](https://github.com/twvn-dev-community-coding-challenge/coding-challenges/blob/073894bc3dc2570f0ca3cfeea5f7daa774654d67/coding-challenge-3/jameslu/internal/dispatch/offer.go#L48)). A delayed scheduler allows an expired offer to become accepted and stops its timer.

**Verification:** reviewer clock returns a time one hour past stored expiresAt while its callback has not run. ### Scalability & Performance Design — 5/5

Driver.Available scans a mutex-protected full map and sorts available IDs; Matcher computes Haversine and sorts candidates. Work is O(n + a log a + k log k), with O(a+k) result allocation, for n drivers/a available/k in radius. OfferStore.Create and Excluded also scan all retained offers under one mutex. The docs recognize geo-scan/location-write/hot-driver/claim-store/broker bottlenecks, though offer-history contention merits an additional future index.

The proposed 1K→100K→1M path separates hot locations from transactional claims, uses geo shortlists, regional databases/claims, partitioned brokers/workers and cached read models. Location write estimates of 250/25K/250K per second are explicit assumptions based on four-second reports, not benchmarks. Cell edges and cross-owner claims still need authority/fencing; stale cached status can be rejected at claim but does not guarantee exact latest physical proximity. These are design proposals and trade-offs, not implemented production capacity.
