# ADR-007: Language and libraries: Go with the standard library first, plus a few focused drivers

* **Status:** Accepted
* **Date:** 2026-11-01
* **Requirements:** team constraint T2 (Go)
* **Related:** [architecture §14](../architecture.md#14-repository-layout) (code layout)

## Context

The team chose Go (T2). The guiding rule for libraries: **standard library first; one well-maintained, focused library where the standard library has nothing.** No frameworks that hide the mechanisms the challenge asks us to explain (transactions, offsets, locks).

## Part 1: language

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| **Go 1.27** | ~20 MB static binaries; millisecond start-up; goroutines fit "consumer loop + relay + sweeper + HTTP server" per service; mature pure-Go drivers; explicit code | Fewer ready-made frameworks (we write small pieces ourselves) | ✅ **Chosen** |
| Java 21 + Spring Boot | Richest saga/messaging ecosystem (Spring Kafka, Axon) | 200+ MB images and RSS per service; frameworks hide transactions and offsets | Strong alternative, too heavy for a laptop VM |

## Part 2: libraries

| Need | Chosen | Why |
|---|---|---|
| HTTP routing | `net/http` `ServeMux` (Go 1.22+ patterns) | `GET /rides/{rideId}` routing and `r.PathValue` in the standard library; no framework needed |
| PostgreSQL | `jackc/pgx/v5` + `pgxpool` | Fastest Go driver; native types; Postgres error codes. No ORM: an ORM would hide the `FOR UPDATE` and conditional `UPDATE … WHERE` row counts that [ADR-002](ADR-002-concurrency.md) depends on |
| Kafka / Redpanda | `twmb/franz-go` | Pure Go (no cgo); idempotent producer; manual commits; `BlockRebalanceOnPoll`; recommended by Redpanda |
| Redis | `redis/go-redis/v9` | Official client; typed GEO commands; Lua scripts; `redisotel` tracing |
| gRPC (API v2) | `google.golang.org/grpc` + `protobuf` | The reference implementation; code generated by `protoc-gen-go` / `protoc-gen-go-grpc` and committed ([ADR-010 Part 6](ADR-010-api-and-identifiers.md#part-6-grpc-api-v2-for-two-driver-app-apis)) |
| Migrations | Embedded SQL files + a 60-line migrator (`pgutil.Migrate`) | No dependency for ~6 SQL files; migrations ship inside each binary; an advisory lock makes them safe with replicas |
| IDs | `google/uuid` **v7** | Time-sortable, standard ([ADR-010](ADR-010-api-and-identifiers.md)) |
| Logging | `log/slog` | Standard library ([ADR-005](ADR-005-observability.md)) |
| Telemetry | OpenTelemetry Go SDK + `otelhttp`, `otelgrpc`, `redisotel`, `otelslog` | Vendor-neutral ([ADR-005](ADR-005-observability.md)) |
| Lint | `golangci-lint` v2 ([.golangci.yml](../../.golangci.yml)) | Bug-finding linters + gofmt/goimports; the same pinned version runs in CI |
| Configuration | Environment variables (`svc.Env`, `svc.Duration`) | Enough for ~10 settings |
| Dependency injection | Manual wiring in each `cmd/main.go` | The Clean Architecture composition root ([ADR-012](ADR-012-clean-architecture.md)); no DI framework needed for 3 small services |
| Testing | `testing` + `testcontainers-go`; `getkin/kin-openapi` (e2e only) | Real Postgres/Redis in tests; REST responses validated against the OpenAPI spec ([ADR-011](ADR-011-testing-strategy.md)) |

## Decision

Go 1.27, one Go module, standard library first. Third-party code only for drivers and protocols: pgx, franz-go, go-redis, gRPC/protobuf, OpenTelemetry, uuid; for tests: testcontainers, kin-openapi.

## Consequences

* ✅ ~20 MB images; services start in milliseconds; low memory in the Colima VM.
* ✅ Every important mechanism (transactions, conditional updates, offsets, retries) is visible in our code.
* ⚠️ We wrote small pieces a framework would provide: the outbox relay, the consumer loop with retry/DLQ and the migrator (~500 lines in `pkg/`).

## When to revisit

* Many more queries: add **sqlc** for compile-time checked SQL.
* Several workflows: **Temporal Go SDK** ([ADR-003](ADR-003-saga-orchestration.md)).
